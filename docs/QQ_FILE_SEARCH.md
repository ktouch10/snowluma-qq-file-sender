# QQ 本人私聊查找与转发

本功能与 MCP/CLI 共用文件发送核心，但使用单独的可信 OneBot 正向 WebSocket 事件连接。所有指令都必须来自 `recipientQQ` 本人的私聊。只有群文件元数据被查询，群消息不会执行文件操作。不需要模型，也不会将文件正文或群文件列表交给模型。

## 配置与启动

1. 完成 README 的 Node.js 24+、本机 SnowLuma、固定收件人和 HTTP 网关设置。
2. 创建运行目录、允许的搜索目录及中转目录；例如 `D:/file-sender-home/outbox`。不要把整个盘或用户主目录设为搜索根。
3. 参考下面配置修改运行目录里的 `secretary.json`。将占位符替换成自己的值，`allowedGroups` 默认空数组表示不查询任何群；只填写机器人实际有权访问且你同意检索的群。
4. 在 SnowLuma 启用本机正向 WebSocket（事件端点 `/event` 或 `/`）；端口取决于自己的后端配置，示例 3001 不是自动检测值。HTTP 和 WebSocket 令牌需要一致，均使用环境变量 `ONEBOT_ACCESS_TOKEN`。
5. 设置 `FILE_SECRETARY_HOME` 后，在项目目录运行 `npm run listen`。保持这个进程及 QQ/SnowLuma 在线，后续每次传文件无需重新启动它。

```json
{
  "enabled": true,
  "recipientQQ": "YOUR_QQ",
  "gatewayUrl": "http://127.0.0.1:3000",
  "sourceRoots": ["D:/agent-output", "D:/file-sender-home/outbox"],
  "search": {
    "enabled": true,
    "receivePrivateMessages": true,
    "wsUrl": "ws://127.0.0.1:3001/event",
    "localRoots": [
      {"path": "D:/documents", "label": "文档", "kind": "documents"},
      {"path": "D:/agent-output", "label": "产物", "kind": "outputs"}
    ],
    "allowedGroups": []
  }
}
```

电脑桌面、下载等位置需要自己添加对应真实路径，`kind` 可用 `desktop`、`downloads`、`documents`、`outputs`；`label` 是候选显示名称。没有自动发现用户目录或整盘扫描。`sourceRoots` 必须明确包含当前 `FILE_SECRETARY_HOME/outbox`，否则查到文件后发送准备会被拒绝，程序不会偷偷扩大权限。

从 0.1.0 升级仅用 MCP/CLI 的用户，无需添加 `search`，原接口和参数保持兼容。不要将独立监听服务与另一套已经处理相同私聊文件指令的桥接控制器并行运行。

## 在 QQ 中使用

| 发送给机器人 | 行为 |
| --- | --- |
| `文件帮助` | 显示命令 |
| `找文件 项目报告 pdf` | 查允许的电脑目录及群文件，多个关键词都必须匹配文件名 |
| `找群文件 高数 复习` | 只查允许的群 |
| `找电脑文件 项目报告` | 只查电脑 |
| `帮我把桌面上的项目报告PDF发给我` | 只查 `desktop`；明确发送、唯一且完整匹配时直接发送 |
| `发送第2个` | 发送最近一次候选的第 2 项，10 分钟内有效 |
| `文件状态` | 查看通过此入口产生的最近发送记录 |
| `取消找文件` | 取消候选选择；不能撤回已经开始的上传 |

按文件名查找，不能回答“找正文提到某事的文件”。候选最多 6 个，含名称、来源标签、大小、日期；不会在回复中显示电脑绝对路径。群来源会显示已允许群的编号，仅发给配置的本人。文件名护栏不能识别正文内的所有秘密，应只开放愿意发回本人 QQ 的目录和群。

## 存储、限额与恢复

业务数据全部放在 `FILE_SECRETARY_HOME`：`search-data/requests.json` 保存候选、消息去重和发送来源关联，`outbox/found-files` 是短期中转副本，`deliveries` 是原发送核心的副本与状态。配置在其他磁盘即可避免业务缓存占系统盘。

- 只支持普通文档、图片、视频、音频及常见压缩包，单文件不超过 32MiB。隐藏目录、凭据、配置、日志、状态、依赖目录及下级链接不参与搜索。
- 本机最多配置 12 个根目录，一次扫描最多 16,000 项、8 层，约 6 秒调度预算；慢磁盘单次读取仍可能超过预算。
- 群一次最多 8 个、根目录加 3 层文件夹、16 次列表请求、6,000 个文件，约 20 秒调度预算。接口每次最多 10 秒；列表缓存 90 秒。未搜完会明确提示，不会据此自动判定唯一发送。
- 群列表能看到不代表下载一定可用；QQ 不提供 URL、文件过期、权限不足或长度不符都会停止，不能报告已发出。
- 下载仅接受后端生成的 `ftn.qq.com` 及其子域 HTTPS URL，不接受用户输入 URL、HTTP 下载、跳转或私有 IP。目前下载依赖公网 IPv4；仅 IPv6 环境未支持。TUN 只返回 `198.18/15` 时，会向固定 Cloudflare 公共 DNS 查询该已允许 QQ 域名，校验真实地址后直连；不是允许访问 fake-IP。
- 事件最多保存 256 条、7 天；发送关联最多 64 条，普通关联 7 天后清理，不确定关联继续保留。中转超过 24 小时的 UUID 目录在下次中转清理，最多同时容纳两份 32MiB 文件；实际上传仍走原核心 64 条/128MiB 限额。
- `gateway-accepted` 只表示网关受理。`unknown`、`sending`、异常退出锁都需要先查看 QQ，不能删记录换 ID 碰运气。相同来源的新搜索也会复用不确定记录，避免意外补发。
- 正常 Ctrl+C 退出释放监听锁；崩溃遗留 `listener.lock` 或 `request.lock` 时，先确认旧进程已结束、检查 QQ 和 `deliveries`，再由管理员处理锁。不要在旧上传仍运行时清理。
- 更改收件人或 HTTP 网关后，原搜索状态拒绝使用。停止旧监听，改用新的运行目录；旧记录保留供核查，不能混给新收件人。

事件连接断开会重连；这是重新接收事件，文件上传不会自动重试。服务不保存聊天历史、不安装开机启动、不管理 QQ 登录。

## 维护与验证

`src/secretary-search.js` 负责解析、允许范围、候选及持久化；`src/qq-listener.js` 负责可信事件与固定本人回复；`src/qq-download.js` 负责域名、DNS/IP 固定、TLS 和下载限额；`src/secretary-files.js` 仍负责最终文件副本与上传。

`npm test` 全部使用假事件、模拟网关与模拟下载，不连接真实 QQ。首次实机验收用自己的非敏感小文件：先找候选，选中一次，核查 QQ 收到且能打开，再记录验收；不要把模拟成功当作真实投递确认。
